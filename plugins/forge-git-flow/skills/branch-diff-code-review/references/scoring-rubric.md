# Scoring rubric（100 分評分規則）

## 總則
- 起始 100 分，按缺陷扣分；也可用「達成度」給分，但必須可解釋。
- 扣分必須對應到具體檔案/區塊與理由，避免「感覺不好」。

## 拆項（加總=100）
1) Correctness & Reliability（30）
- 邏輯正確、邊界條件、null safety、錯誤處理、狀態一致性
- 典型扣分：
  - 可能 crash / 競態條件 / 不可恢復錯誤：-5 ~ -15
  - 容易造成資料不一致：-5 ~ -12

2) Architecture & Design（20）
- 分層責任、耦合度、可擴展、依賴方向
- 典型扣分：
  - UI 混入商業邏輯、Repo 直接操作 UI：-3 ~ -8
  - 重複邏輯未抽象：-2 ~ -6

3) Readability & Maintainability（15）
- 命名、結構、可讀性、重複、註解品質
- 典型扣分：複雜度高但無拆分/命名含糊：-2 ~ -6

4) Testability & Tests（15）
- 是否容易測、是否補測、關鍵路徑是否被測到
- 典型扣分：
  - 關鍵行為無測試且難測：-4 ~ -10
  - 已有測試但未更新導致失真：-3 ~ -8

5) Performance & Resource（10）
- 主執行緒阻塞、列表效能、重組/重繪、記憶體、IO
- 典型扣分：明顯效能坑：-2 ~ -8

6) Security / Privacy / Compliance（10）
- 敏感資訊、權限、token、加密、日誌、傳輸
- 典型扣分：
  - 明顯敏感資訊外洩風險：-5 ~ -10（通常直接 P0）

## 評分輸出格式要求
- 必須列出：
  - 每項得分（或扣分）
  - 扣分原因（指向具體檔案/行）
  - 總分
- 必須附上一句「這個分數意味著什麼」（例如：可合併/需修正/阻擋合併）
