# Kickoff Prompt 模板

> 新 session 沒有這次對話的任何記憶。prompt 要讓它**不必回頭問**就能開工，也知道什麼時候算做完。
> 固定五段、順序不變。每段先回答下列問題，答不出來的寫「未知」並放進「交接資訊」的待確認清單，不要編造。

---

## 骨架

```markdown
## 背景
<專案是什麼、用什麼技術棧、這次需求從哪裡來>

## 目標
<這次要完成的一件事，一到三句>

## 驗收條件
- [ ] <可觀察的完成判準 1>
- [ ] <可觀察的完成判準 2>

## 限制
- <不能做的事、不能碰的範圍、必須遵守的慣例>

## 交接資訊
- 相關檔案：<路徑>
- 驗證指令：<指令>
- 待確認：<掃描時答不出來的問題>
```

---

## 各段要回答的問題

### 1. 背景

- 這個 repo 是做什麼的？（取自 README 第一段或 CLAUDE.md 開頭，一句話）
- 主要語言、框架、建置工具是什麼？（取自套件或建置檔）
- 這次需求的起因是什麼？使用者原話是什麼？（原話保留，不改寫）
- 有沒有規格檔可以參考？（有就寫出路徑與抽出的段落標題）

### 2. 目標

- 做完之後，什麼東西會跟現在不一樣？
- 這件事的邊界在哪？（只做 A，不順手做 B）
- 如果目標有多個，哪一個最優先？

### 3. 驗收條件

- 怎樣算做完？每一條都要能被觀察或執行驗證（指令、測試、肉眼可見的輸出）
- 要跑哪些測試或檢查？預期結果是什麼？
- 有沒有「行為不變」的要求？用什麼方式確認？
- 規劃類任務：產出是什麼檔、要涵蓋哪些決策點？

### 4. 限制

- 專案慣例裡和這次有關的規則是哪些？（取自 CLAUDE.md，只挑相關的，不整份照抄）
- 哪些檔案或目錄不能動？
- 哪些操作需要先問使用者？（push、刪除、改共用設定、對外發布）
- 有沒有版本號、文件同步之類的連帶義務？

### 5. 交接資訊

- 掃描時看過哪些檔？哪些和需求直接相關？
- 驗證用的指令是什麼？（從 CLAUDE.md、README、建置檔取，原樣寫出）
- 需求點名的對象在 repo 裡找得到嗎？找不到就明寫「掃描時未找到 X」
- 工作區狀態（乾淨 / 有未 commit 改動）
- 還有哪些問題沒有答案？新 session 開工前要先確認什麼？

---

## 寫作規則

- 用繁體中文；檔名、指令、識別字保留原文
- 只寫掃描看得到的事實，推測要標「推測」
- 總長度盡量控制在 5,000 字以內，讓 deep link 可用；超過時優先刪減「背景」與「限制」中與需求無關的部分
- 不要在 prompt 裡寫 model、effort、permission mode——那些由啟動指令帶
