# Business logic heuristics（商業邏輯建議角度）

目標：不要只當語法警察。要能指出「這會不會讓產品行為變怪、指標變假、客服爆量」。

## 必問四件事（每個功能改動都要過一遍）
1) 使用者看得到的行為有沒有變？（流程、文案、錯誤提示、成功/失敗條件）
2) 失敗/重試/離線時怎麼辦？（降級策略、重送、冪等）
3) 觀測與追蹤有沒有跟上？（埋點、log、error report、關鍵指標）
4) 邊界條件與例外狀態是否可解釋？（空資料、部分成功、權限不足、時區/金額四捨五入）

## 常見高風險域（命中就要多寫幾句）
- 登入/驗證/權限（任何繞過都可能是事故）
- 支付/訂單/交易（狀態機、冪等、重入）
- 金額/利率/手續費（精度、四捨五入、幣別）
- 推播/通知（頻率控制、重複發送）
- 分析/埋點（事件命名一致性、漏打、重複打、時機錯誤）
- 資料同步（本地快取 vs 伺服器一致性）

## 建議輸出型態（要可行動）
- 「我建議補上一個 guard：……，因為……」
- 「這裡的狀態轉移缺少 X → Y 的處理，可能導致……」
- 「埋點事件在成功前就送出，可能讓轉換率虛高，建議改為……」
- 「錯誤被吞掉，客服只會看到『轉圈圈』，建議至少……」
